# 和AI一起学习 · 持续迭代路线

## 网站主线

用真实学习和实践的积累展示变化：读到什么 → 产生什么问题 → 做过什么尝试 → 得到什么结果 → 下一步继续研究什么。个人简介作为背景，首页优先展示最新学习动态。仅使用本人确认可公开的资料。

## 已完成的第一轮

- AI 日报首页入口、按日期归档的目录与单篇阅读页。

## 2026-10-12 阅读体验改版

- 首页、日报目录和正文统一使用暖白、墨绿的阅读主题；手机端提供可展开导航。
- 日报目录支持全文关键词、日期、主题与收藏组合筛选，筛选条件保留在网址中。
- 日报支持本机收藏；收藏仅保存在当前浏览器，存储不可用时页面明确提示。
- 正文提供章节目录、阅读进度、预计阅读时间、原始来源展开和复制链接。
- 项目记录补充可展开说明，学习内容仅呈现已经确认的事实和待探索方向。

### 维护方式

共享样式与交互位于 `assets/site.css` 和 `assets/site.js`。`scripts/build_daily.py` 生成日报目录、每期正文以及首页 `DAILY:START` / `DAILY:END` 标记之间的最新内容，不再从首页复制整段 CSS。更改模板后运行生成器即可同步历史文章；新增日报沿用现有 JSON 格式和发布流程。无需安装前端依赖。

## 日报更新方式

1. 从本人指定的 ChatGPT“每日重点简报”读取当天新内容。
2. 筛选与 AI 学习有关的 3—5 个主题；不为凑数收录不相关内容。
3. 找到可靠原文，核对关键事实、消息日期和数字口径。原始报告中的聊天引用标记不能充当网页来源链接。
4. 为每条消息补一个学习问题；只有本人提供的想法才标作“我的想法”。
5. 写入 `content/daily/YYYY-MM-DD.json`，核验完成后设置为 published。
6. 在仓库根目录运行 `python scripts/build_daily.py`，生成日报目录、单篇页面和首页最新日报入口。
7. 检查页面和本地链接，提交本次日报文件及生成结果，推送 main，确认 Pages 构建对应本次提交。

每天最多新建一期；同一天的修正更新原文。没有新日报时不制造新文章。来源不足时保留草稿，已发布历史文章继续保留。首期之前的历史简报可逐步回填，按真实报告日期归档。

## 自动化的运行边界

当前使用本机 Codex 对话的定时跟进读取日报、核验并发布，本机和桌面应用需要保持运行；这项定时跟进不负责生成原始 ChatGPT 日报。发布脚本本身不调用付费模型 API。

后续如果需要电脑关闭后仍全天运行，可以评估 Muse 等常驻助手，或迁移到云端任务。连接、读取来源和仓库权限需要实际验证后再接入。

## 文章数据格式

参考 `content/daily/2026-10-11.json`。重要字段：整理日期 date、标题 title、导读 summary、时点说明 coverage、主题 topics、新闻列表 items、建议练习 learning_suggestions。每条新闻包含消息日期、摘要、AI 解读、学习问题，以及名称、网址、发布日期齐全的来源列表。

生成器会拒绝缺少来源、未完成核验、日期错误或状态未知的公开日报。事实核验由整理流程负责，生成器只能检查数据结构，不能判断新闻是否真实。
